## 4. 오류가 발생하는 계층

브라우저 입력창은 학점 범위를 검사합니다. 다음 요청은 그 화면 검사를 거치지 않고 **서버의 입력 검증**을 관찰합니다. 개발자 도구 Console에서 아래 블록을 하나씩 실행하고 Network 탭에서 응답을 확인합니다. 붙여넣기가 차단되면 브라우저의 보호 설정을 끄지 말고 직접 입력하거나 교수자 시연으로 관찰하세요.

```js
fetch('/api/students/1001', {
  method: 'PATCH',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({tot_cred: 201})
}).then(r => r.json()).then(console.log)
```

예상: HTTP 400, 애플리케이션 검증 실패. 학번 1001의 학점은 42를 유지합니다.

```js
fetch('/api/students', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({id: 2004, name: '학과오류', dept_name: '없는학과', tot_cred: 0})
}).then(r => r.json()).then(console.log)
```

예상: HTTP 409, DB 외래키 제약 위반. 학생 2004는 추가되지 않습니다.

질문: UI 검사, 서버 검사, DB 제약조건은 각각 어떤 역할을 하나요?
